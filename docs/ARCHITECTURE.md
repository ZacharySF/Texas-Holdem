# Architecture decisions

## Scope

The repository began empty and shipped Phases 0–1 first. Subsequent requests authorized Phases 2–4, Phases 5–7, and then the remaining Phase 8–9 work recorded below. The current request covers GitHub publication and local startup of the completed Phases 0–9 application.

## Core boundaries

Cards use rank-major integers: 4 × (rank − 2) + suit, where suits are clubs, diamonds, hearts, spades (0–3). This makes rank and suit extraction inexpensive; strings are only input/output. Evaluator strength uses category and five base-15 rank digits; larger integers win. The fast evaluator counts ranks and suit masks directly for five through seven cards. The independent reference evaluates each five-card subset using sorted groups and selects the maximum. No bundled lookup asset is needed; the tradeoff is arithmetic per hand rather than a larger table.

xoshiro128** is initialized from a 128-bit hexadecimal seed; the all-zero state is rejected. A rejection threshold removes modulo bias before reducing bounded integers. User-facing seed creation belongs outside the pure engine. Monte Carlo draws a partial Fisher–Yates permutation from the remaining deck for each trial; exact enumeration visits unordered boards and unordered hole-card pairs for each labeled random opponent. Fixed hands and dead cards remove cards first.

Equity accumulates integer win/tie/loss counts and exact pot-share units (LCM of possible winner counts). Exact equity is a rational even in multiway ties. Sampled fractions describe observed frequencies, not exact underlying probabilities. A normal interval using Welford variance describes mean pot share; Wilson intervals describe binary win/tie/loss frequencies. At sample boundaries, equity uncertainty also uses a bounded-outcome safeguard so zero observed variance does not imply certainty.

The worker runs a pure generator in small batches, yields to its event loop, and posts throttled progress. Cancellation terminates the worker immediately; each run has a fresh worker so stale messages cannot overwrite current results. Exact feasibility is based on total assignments multiplied by player count, calibrated conservatively using benchmark throughput. Large exact jobs remain available in the engine and verification scripts, not on the main UI thread.

All card state, seed, sample count, and chosen method are URL parameters under HashRouter. Settings, lesson mastery, and the play-money profile use localStorage; completed hand histories use IndexedDB. Invalid saved settings fall back safely. No data leaves the browser. Weighted ranges extend the player-input union and assignment generation in Phase 3.

## Verification and delivery record

The complete five-card and seven-card counts and distinct five-card strengths passed, as did 100,000 default and 1,000,000 slow reference comparisons. The slow verification took 22.1 seconds for enumeration and 14.5 seconds for reference comparisons on the README machine. No table assets are bundled.

Pin Node 24.20.0, the available Node 24 LTS runtime in this environment, rather than requiring a new system installation. Runtime setup used `nix shell nixpkgs#nodejs_24`; the standard setup remains nvm/npm. The [Node release schedule](https://nodejs.org/en/about/previous-releases) documents LTS support. Pages follows the [custom workflow contract](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

A 120,000 evaluation budget intentionally leaves headroom for slower phones and exact assignment-generation overhead. It is conservative rather than an on-device timing probe; the measured desktop benchmark is much faster. Exact enumeration above that limit is available through the engine and scripts. Only sampled estimates get sampling intervals during progress: an ordered, incomplete enumeration is not a random sample. Complete exact intervals collapse to the rational result.

Monte Carlo pot-share confidence intervals are approximate pointwise normal intervals with a minimum radius of z²/(n+z²) at the boundaries. Wilson is used only for the binary win/tie/loss events; a multiway fractional share is not treated as a Bernoulli outcome. Repeated chart updates do not create a simultaneous confidence guarantee. Statistics lessons will build and explain these assumptions when their phases arrive.

Lab defaults are written into the URL immediately, including the freshly generated seed. A browser replay check caught the consequence of leaving the initial seed only in memory: reload changed the default experiment. Persisting the default URL fixes that boundary. Seed editing uses a draft field and validates on commit, so partially typed seeds do not corrupt shared state.

Workers retain roughly 250 evenly spaced convergence checkpoints per sampled run while batching messages around 50 ms. This preserves a visible convergence path even when a small simulation finishes before the first timed progress update. The checkpoint count is bounded independently of the requested sample count.

## Phase 2: lessons and mastery

Ten individually loaded MDX modules cover the two objectives/lessons in each chapter 0–4. A shared context supplies a lesson definition and one URL seed to the seven-part component contract. NotebookBlock renders aligned KaTeX with HTML and MathML, trusted commands disabled, and formula errors treated as failures. Fonts and content are bundled locally. The [MDX Vite integration](https://mdxjs.com/docs/getting-started/) runs before the React plugin; [KaTeX rendering](https://katex.org/docs/api) uses application-authored expressions only.

Engine experiments keep an event predicate separate from its exact counting formula. Tests enumerate the predicate's actual ordered outcomes to verify the formula. A worker deals independent trials from restored populations, retaining bounded chart checkpoints, Wilson intervals, and a reproducible seed. Binary event frequency is deliberately distinct from pot-share equity. The facts registry supplies symbolic notebook lines, arithmetic results, probability conversions, shortcut errors, and the mastery threshold.

Practice generates five questions from the same lesson seed, grades exact rational equivalents (including finite decimal, percent, one-in, and odds-against input), reveals each full solution only after submission, and records only completed sets. Best score and attempt count are versioned and validated on localStorage read. Four correct answers establish mastery. Chapters unlock in sequence; the optional introduction can be explicitly skipped, and every chapter remains manually accessible. Unfinished answers reset on leaving or changing the seed; the UI says so. This avoids silently awarding mastery from an incomplete set.

## Phase 3: betting and settlement

Game state is pure data. Actions clone the state, validate whose turn it is, debit only legal integer chip amounts, and either select the next pending actor or advance the street. Hole cards are dealt clockwise starting left of the button, so the heads-up big blind receives the first card. Heads-up button/small-blind action order is first preflop and last postflop. Each street resets the minimum increment to the big blind. Full raises update the increment and reopen action; a short all-in leaves the prior increment intact. A previously acting player can raise again only after facing a cumulative full increment. Burn cards are included in the seeded deck sequence.

Uncalled excess is returned before settlement or street advancement. Pot layers use contribution thresholds, retain folded players' money, restrict eligibility to live contributors, and split ties with odd chips assigned in seat order left of the button. Final awards clear live contribution counters so stacks plus pot remain conserved. Replay rebuilds the initial deal and applies the recorded action sequence. The engine accepts multiple seats for rule/property verification, while the Phase 3 UI exposes only two seats.

## Weighted ranges and information boundaries

A range is a list of distinct two-card combos with positive integer relative weights. Known/dead cards remove blocked combos. Exact calculation enumerates compatible joint hole-card assignments and remaining boards, accumulating BigInt weight and pot-share totals. Samples draw independent prior combos and reject the entire joint assignment on collision; sequentially conditioning each player's draw would bias earlier players. A rejection cap reports pathological overlap instead of silently switching distributions. Exact planning uses a conservative assignment upper bound; the completed result reports the actual enumerated count.

Bot workers receive PlayerView only: their own cards, community cards, public contributions/stacks, legal options, position, and public actions. No opponent cards, deck order, cursor, or deal seed enter that payload. Tests alter hidden cards/deck/seed while asserting an unchanged view. The original persona mix has been replaced by sampled legal-action return comparisons, described in the bot follow-up below. Range weights are documented heuristics based on rank structure and public aggression, not learned opponent frequencies or equilibrium strategies. For its human opponent, a bot uses its persona's same weighting heuristic as a prior; the coach uses the selected bot persona.

Coaching computes call EV relative to folding and excludes a known uncallable overbet from the contestable pot before pricing a short-stack call. Check EV assumes checking to showdown. Raise EV assumes the displayed fold probability, otherwise one call and no subsequent betting; the called range is held fixed. Grades compare those conditional models, not optimal play. Improvement outs count cards that increase the current made-hand category; fixed-set next-card/by-river probabilities do not claim that every improvement wins. Phase 4 adds coach links to card removal (5.1), board texture (7.2), drawing odds (8.1), and dirty/overlapping outs (8.2). Chapter 12 now supplies the full EV lesson.

## Commitment, history, and progression

The UI generates a crypto seed, hashes its UTF-8 hexadecimal text with Web Crypto SHA-256, displays that commitment, and requires a separate Deal action before creating the hand. The seed appears after completion, with verification against the pre-deal hash. Decision and runout seeds use separately labeled SHA-256 derivations so displaying an analysis seed does not reveal the deal seed. Local commitment verifies consistency/replay; all local program state remains inspectable by the browser owner, so it is not an independent adversarial fairness service.

Completed records in IndexedDB contain the initial configuration, commitment, actions, decision estimates/seeds/grades, and exam guesses. Post-hand x-ray shows bot cards and reasons. Replay changes the displayed action index; run-it-out selects any encountered street and samples 10,000 showdowns with both disclosed hands. Chip-outcome bars use final matched contributions and the same split-pot rules, not a claim to simulate later betting decisions.

The profile awards each completed seed once, updates the play-money bankroll by actual stack change, adds hand/decision XP, and derives lesson XP from mastered lessons. Stakes and personas unlock from total XP; a busted bankroll can be explicitly refilled. Active hands are session-only and are not settled when abandoned. This is a deliberate small-scope persistence choice; resumable active tables are deferred rather than claiming a recovery guarantee.

## Phase 4: counted card experiments

Nine new MDX lessons cover all chapter 5–8 objectives with the established seven-part contract. The facts registry re-exports drawing facts from a separate content module so lesson prose, practice, simulations, and diagrams share definitions. Exact answers remain BigInt rationals. Rare nonzero percentages keep significant digits instead of rounding to zero; the fraction remains the exact representation.

CourseDraw extends the existing typed experiment protocol. Card removal, fixed outs, royal flushes, common flop events, and five-card category frequencies use counting formulas. Board textures, one-card straight draws, and exposed-hand showdown events enumerate their small remaining sample spaces; a bounded cache avoids repeating those calculations while rendering. Monte Carlo runs in the existing worker, with selectable event definitions, cancellation, sample counts, Wilson intervals, exact references, and signed gaps. A million-trial option makes rare-event experiments useful while preserving bounded convergence traces.

Seven-card categories use cached exhaustive counts. Deriving every category by overlapping five-card subsets would double-count deals; the lesson instead explains an exact increasing-card-set enumeration and strongest-category classification. The tradeoff is a tiny verified count table rather than a long blocking enumeration during a page render. `verify:7card` now checks the facts-registry table and royal fraction directly. This phase reran all 133,784,560 sets (21.427 seconds) and one million independent reference comparisons (14.771 seconds). Five-card formulas are checked against both exhaustive evaluators in the default suite. Suit textures also have independent counting checks after card removal.

Event definitions are explicit. The supplied set-mining anchor 144/1225 means the pocket-pair rank appears at least once on the flop. It excludes a three-of-another-rank flop that makes a full house without hitting that rank; the phrase “set or better” alone is ambiguous. The full-board anchor uses the same rank-hit event over five board cards. An exact flush draw means precisely two extra suited cards; a made flush includes straight flushes. A straight draw means no made straight and at least one one-card completion. Paired board includes trips. These choices appear in the lesson text and simulator labels.

Outs are sets of physical cards meeting an explicit target. Flush/straight unions remove overlap; exposed-opponent examples separately compute next-card cards that put the hero ahead, excluding ties. Fixed-out hit rates are not showdown equity or a guarantee against river redraws. Play still uses its documented visible-information category-improvement model and links to the new lessons; hidden cards remain excluded.

## Phase 4: Outs Rush and persistence

Outs Rush draws five templates without replacement and permutes suits with the seeded PRNG. Templates include flushes, open-ended and gutshot straights, combo draws, one-card misses on a backdoor draw, dirty outs against exposed cards, and drawing dead. Each question computes its answer by inspecting every available next card. The URL seed recreates the sequence; time limits do not affect dealing.

Timing uses elapsed monotonic time, checks the deadline at submission, and locks each answer once. Learners can pause or choose untimed practice. Expiry reveals the same full solution and waits for explicit advancement. A completed set updates its best score in versioned localStorage; each improvement adds drill XP to Play, and replaying the same correct answers cannot duplicate that XP. Partial sets award nothing. Shared card presentation moved into src/ui so lessons, Play, and Arcade share suit symbols, themes, and reduced-motion behavior.

Permanent browser smoke tests remain Phase 9. Phase 4 adds focused component tests for timing, pause/resume, expiry, delayed solutions, completed scoring, storage, and replay; the production app also receives a manual Chromium interaction review. The later sections record the subsequent Phase 5–7 implementation. Existing external Pages setup and active-hand recovery limitations are unchanged.

## Phases 5–7: distributions and learning

The explicit delivery scope now extends through Phase 7. Hypergeometric and binomial counts, geometric waits, inclusion–exclusion for higher pocket pairs, Bayes, and beta-binomial prediction have independent normalization and controlled-example tests. The analysis worker runs typed model experiments and bankroll paths. Binary indicators use Wilson intervals; numerical payoffs and sample means use normal mean intervals and display their assumptions. The LLN/CLT control changes observations inside each trial, separately from the number of repeated trials. Interval coverage is itself an experiment, with its exact answer found by summing binomial masses whose Wilson intervals contain the supplied truth. Pointwise intervals are explicitly distinguished from simultaneous convergence guarantees. Actual-card matchup and range experiments continue to use the equity worker.

The event builder composes a counted card predicate with independent repeated hands and exact or at-least success counts. Its simulation actually deals each base event afresh. URLs retain event parameters and seed. ## Phases 5–7: drills, bankroll, and Stats

Call or Fold states a fixed rake and supplied equity; its solution computes incremental EV after rake. Guess the Equity enumerates every legal river against an exposed hand. The Brier target is a binary randomly selected pot unit: ties assign that unit with a seeded coin so its expectation equals equity. Exact-equity squared error is reported separately. Forecast outcome streams use labeled SHA-256 seed derivations distinct from the question-generation stream. Combo Counter independently removes shown physical cards. All three drills have seeded five-question sets, optional clocks, pause/resume, delayed worked solutions, and manual advancement after expiry.

Only completed sets persist. Forecast records retain the first completed observation for each mode/seed/question; replay neither adds independent calibration evidence nor duplicates XP. This differs intentionally from Outs Rush's best-score progression because replacing a forecast after seeing its outcome would contaminate calibration. Storage failures leave results usable in memory. Stats shows calibration counts, Brier scores, and Wilson intervals, alongside the time series of scores.

Bankroll simulation uses independent normal increments per 100-hand block; the final partial block scales its mean and variance by length. Inputs are win rate, block SD, hands, bankroll, and at least two paths. Outputs include final results, maximum drawdowns, longest time below a prior peak, and ruin frequency with uncertainty. Ruin is measured at block endpoints; paths continue afterward to preserve the unconstrained result distribution. This affordable approximation omits within-block ruin, serial dependence, strategy changes, and parameter uncertainty. These limits are visible beside the controls; this phase does not implement Kelly or a betting policy.

Stats reads completed IndexedDB histories and computes results in a worker. Each hand is normalized by its own big blind. Win-rate intervals and a normal-approximation test use the observed per-hand variance; tiny samples and nonstationarity are explicitly cautioned. Concept grades group recorded actions by street/action and retain the coach's model limitations.

All-in EV adjustment is pot-specific. Replay locates the earliest recorded commitment point where the final pot's contributors have supplied its layer, eligibility is fixed, and at most one eligible player still has chips. Other still-live seats must no longer be able to enter that pot. At that point each eligible revealed hand is run against the remaining boards, and its expected award replaces only that pot's actual award. A later fold or unresolved deeper-stack contest can delay adjustment; unqualified pots stay actual. This conservative definition avoids pretending all pots lock at the first short-stack shove. It removes runout luck only, not earlier card luck or decision errors.

Small fixed-hand runout spaces are enumerated exactly (up to 60,000 boards automatically); larger spaces use 5,000 seeded samples per adjusted pot. Award intervals use an approximate normal mean interval with a bounded-outcome safeguard for unvarying samples. Summed numerical-error estimates use the sum of interval radii, a conservative correlation allowance across shared runouts, and are labeled separately from poker variance. A labeled SHA-256 stream separates Stats sampling from the dealt hand.

## Phase 7: range editing and six seats

The 13×13 editor maps classes to physical combos with integer relative weights from zero to one hundred. A zero removes the class. Blocked combos are removed before normalization, preserving the existing joint-rejection semantics. The scrollable grid keeps 44px targets on phones; specific hands and board/dead cards use editable card strings. URLs store those strings, weights, opponent mode, and seed. Presets are illustrative distributions, not strategic recommendations.

Heatmaps evaluate class-average equity against random cards or the selected weighted range in a worker. Each cell has its own reproducible derived seed, count, interval, and an exact reference when feasible. Incompatible or pathological classes report a reason and are skipped instead of silently being filled with zero. The histogram weights classes equally to show their spread and explicitly does not claim to be a combo-weighted overall range average. Suit-specific variation remains inspectable with specific-hand equity. Lessons distinguish this distribution from uncertainty in an estimate, and range advantage from nut advantage.

Play now selects two or six seats. The button rotates modulo the chosen table size; multiway blinds and first action use the seats left of the button. A short big blind does not reduce the nominal opening price in multiway play. Six-seat starting stacks vary to exercise side pots. All opponent seats use the selected persona, with their own public-action histories and isolated player views. Hidden folded hands are integrated out as random cards in payout analysis, never exposed to the coach.

The six-seat coach samples complete compatible deals and awards each pot only to eligible seats, including ties and odd chips. It reports call and raise net awards and intervals under an explicit assumption that all live opponents call the selected amount up to their stacks, followed by no future betting. It does not multiply whole-table equity by the whole pot, nor display a misleading universal side-pot break-even equity. Raise editing cancels and refreshes the worker estimate before a new grade can be submitted. Heads-up retains its existing fold-response sensitivity model. Bots remain seeded heuristic strategies, not equilibrium agents.

History, x-ray, and runouts now enumerate all seats. Runouts retain final matched contributions, deliberately reinstate all hands for the counterfactual showdown, and histogram actual net awards from pot settlement. Six-seat property tests cover chip conservation, nonnegative stacks, action order, nominal short blinds, deterministic replay, and hidden-information boundaries. Fixed-board side-pot examples check eligibility and odd chips independently of the sampled mean.

At the end of Phase 7, Phase 8 and 9 product features were not yet included. The later delivery below replaces the temporary browser tooling with a permanent suite. External Pages publication and session-only active hands remain the previously documented limitations.

## Phases 8–9: runouts, experiments, and settlement

The explicit request now authorizes the unfinished Phase 8 and 9 work. Twelve additional lessons complete chapters 20–25, with the existing seven-part structure, seeded practice, computed derivations, and measured shortcut errors. `finalFacts.ts` extends the facts registry; `finalLessonFacts.ts` supplies the worked examples and experiment specifications. Logarithms are introduced as inverse powers before the growth objective and Kelly derivative. Numerical outcomes retain their units instead of formatting chip EV or variance as probabilities.

Run-it-twice is a pre-deal table agreement. Once betting closes with at most one live player retaining chips, two completions use the same shuffled deck without replacement, preserving the exposed prefix and burning normally on each completion. A fold ending the hand and a completed river need no second runout. Replay retains the option in GameConfig and reproduces both boards. Every side pot retains its original eligibility. Exact fractional shares from both boards are combined using BigInt units divisible by all supported tie sizes, then rounded once per pot. Remaining indivisible chips go clockwise left of the button among seats with fractional entitlements. This avoids rounding two tied half-pots independently. Expected fractional share is unchanged; deterministic rounding can shift an individual integer-chip expectation by less than one chip per pot.

The river experiment enumerates all single-river shares and derives covariance for two distinct draws: minus population variance divided by the remaining river count minus one. Tests independently enumerate ordered river pairs. The variance of their average includes this covariance; an independent-runout approximation is shown separately. That one-card covariance identity is not reused for multi-card boards. Stats now samples or enumerates **paired** completions and applies the actual two-board settlement rule for hands dealt twice, including integer rounding. The history's run-it-out comparison deliberately remains a one-board counterfactual and says so beside its controls.

Shuffle Lab visits every index-choice path for naive swaps and Fisher–Yates. Its chi-square p-value uses five degrees of freedom for six ordering categories and states the large-count approximation. A separate finite-source enumeration exposes modulo bias and rejection. Streak probabilities use a surviving-run-length dynamic program, checked against exhaustive binary histories. Streak Trap saves completed seed scores and exposes storage failures. Insurance defines its triggering event, benefit, fair premium, and loading separately; ties are excluded from the linked outright-loss contract.

All sampled final experiments run through a typed worker protocol. Workers accumulate numerical trace points and post batches about every 50 ms; fast runs still return intermediate points for their convergence charts. Cancellation terminates the worker immediately. Mean charts have pointwise confidence bands and exact/model references; full-tree CFR uses an exact best-response plot without an inappropriate Monte Carlo interval. URL state retains calculator parameters and experiment seeds. Calculator edits use an Apply form so an unfinished number or comma-separated list cannot destroy the controls needed to fix it.

## Phases 8–9: bounded strategy and tournament models

The playable AKQ game is three-card Kuhn poker relabeled Q, K, A: ante one, one private card, one possible bet of one, no raises. The bot receives its own rank and public history only. The analytic mixed policy is verified by enumerating every deterministic unilateral deviation. The trainer performs full-tree counterfactual regret updates and reports the reach-weighted average policy. Exploitability is the mean of the two best-response improvements in this precise finite game. Current self-play value alone is not treated as an equilibrium certificate. The explanatory reference is Neller and Lanctot, [An Introduction to Counterfactual Regret Minimization](https://modelai.gettysburg.edu/2013/cfr/cfr.pdf); the implementation and exhaustive response checker are local and inspectable.

The push/fold calculator prices a supplied fold chance and **conditional called-range equity**, with covered risk and opponent call separated. A second, even smaller three-rank ante/shove game supplies an exact, independently verified Nash-range example. We intentionally do not label these toy frequencies a Hold’em Nash chart: solving all Hold’em push/fold interactions is a different state space, and the curriculum explains that distinction. River polarized-bluff fractions and the bettor's bluff break-even fold rate have separate registry functions and anchors.

Malmuth–Harville ICM recursively weights the next finisher by their remaining chip share, for two through six players. Exact fractions conserve the entire prize pool. Zero stacks share remaining lower prizes under a stated simultaneous-elimination convention; the finishing-order simulator requires positive stacks. Equal covered chip swings produce prize gain, loss, bubble factor, and prize-EV break-even chance. Skill, blind pressure, and future play are excluded explicitly.

The ruin model uses fixed even-money unit steps with absorbing zero and target balances. Its exact recurrence is checked independently, including fair and deterministic limits. This differs from the earlier block-normal bankroll simulator. Kelly uses a known Bernoulli probability, positive net odds, divisible wealth, and independent repeatable bets. The growth experiment averages natural-log multipliers. Model probabilities are supplied assumptions; neither output is presented as a recommended wager.
